# Pharma Commercial Analytics Warehouse

An independently implemented MySQL 8.0 analytics warehouse for exploring pharmaceutical commercial operations: prescriber activity, prescription trends, sales-call coverage, representative performance, and territory target attainment.

All records generated by this project are synthetic. They do not represent real patients, prescribers, healthcare professionals, companies, or sales activity.

## Project scope

The repository is designed around a small star-like relational model with operational dimensions and analytical fact tables.

| Dataset | Generated volume | Purpose |
|---|---:|---|
| Prescribers | 3,000 | Prescriber and specialty attributes |
| Representatives | 60 | Sales-force roster |
| Territories | 180 | Territory and region mapping |
| Products | 3 | Product launch and portfolio analysis |
| Prescriptions | 468,000 | Weekly prescriber-product activity (52 weeks) |
| Calls | 40,000 | Sales representative interaction events |
| Quarterly targets | 36,000 | Prescriber-product-quarter targets |

The seeded generator creates reproducible CSV files under data/. Generated data is intentionally excluded from version control.

## Business questions

The SQL analysis is organized around practical commercial questions:

1. Which prescribers contribute the highest prescription volume?
2. Which prescribers show increasing or decreasing activity over time?
3. How does prescription activity compare before and after a sales interaction?
4. How do representatives rank within their regions?
5. Which territories are above or below quarterly targets?
6. How does new-prescriber activity change over time?
7. How is product prescription volume distributed across territories?

The call-window analysis is descriptive. Synthetic observational data cannot establish that a sales call caused a prescription change.

## Technology

- MySQL 8.0+
- Python 3.9+ (standard library only)
- SQL joins, CTEs, conditional aggregation, window functions, and indexing
- CSV-based bulk loading with LOAD DATA LOCAL INFILE

## Run locally

1. Create the synthetic CSV files:

   python3 scripts/generate_data.py

2. Create the database and tables:

   mysql -u root -p < sql/01_schema.sql

3. Load the generated CSVs (run from the repository root):

   mysql --local-infile=1 -u root -p pharma_analytics < sql/02_load.sql

4. Add the query-oriented indexes:

   mysql -u root -p pharma_analytics < sql/03_indexes.sql

5. Run the analysis queries:

   mysql -u root -p pharma_analytics < sql/04_analytics.sql

If the MySQL server rejects LOCAL INFILE, enable local_infile in the server configuration according to your local MySQL setup. Do not enable it on a server you do not administer.

## Data model and assumptions

- Prescription grain: one row per prescriber, product, and week-ending date.
- Call grain: one row per interaction event.
- Target grain: one row per prescriber, product, and quarter.
- Prescription counts are non-negative and new prescriptions (NRx) cannot exceed total prescriptions (TRx).
- Synthetic calls and prescription volume are generated independently. Any observed association is not evidence of causal impact.
- Benchmark results are not claimed in this repository. Validate query plans and execution times on your own MySQL instance before making performance claims.
